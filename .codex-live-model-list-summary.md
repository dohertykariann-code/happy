# Live Claude Model List

## SDK call

The probe uses `Query.initializationResult().models`, not a second call to
`supportedModels()`. A throwaway runtime probe against the installed SDK/CLI
returned five models, and `supportedModels()` returned the exact same array
reference as `initializationResult().models`. Reading the initialization result
therefore obtains the CLI-verified catalog with no redundant SDK request.

## Caching and failure behavior

`detectClaudeModels.ts` keeps one shared promise for the daemon process
lifetime. CLI installs do not normally change during one daemon run, so this
prevents repeated Claude process spawns while still refreshing on daemon
restart. The initialize handshake has a 10-second timeout; errors, missing
runtime methods, and timeouts resolve to `undefined`. The active query is
closed on completion and explicitly aborted/closed during daemon shutdown.

## Async metadata sync

`ApiMachineClient` starts the probe with `void detectClaudeModels()` after its
socket connects, following the immediate keepalive setup. Daemon registration
and session creation never await it. A successful result is sent through the
existing versioned `updateMachineMetadata()` path (`machine-update-metadata`),
which preserves unrelated metadata fields. Both CLI and app machine schemas
declare `claudeModels` optional and catch an unfamiliar future shape as absent,
so old, offline, pending, or failed machines retain the hardcoded picker list.

`SessionView` reads its current machine's `claudeModels` and supplies it to
`getAvailableModels()`. Claude rows map SDK `value`, `displayName`, and
`description` into the existing `ModelMode` shape; absent or empty metadata
uses the unchanged hardcoded Claude fallback.
