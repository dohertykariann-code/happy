# Live Codex model list summary

## Protocol

- Added `CodexAppServerClient.listModels()` for JSON-RPC method `model/list`.
- The initial request uses `{}`: default page size, no cursor, and the server's default hidden-model exclusion. A non-null `nextCursor` is followed once with `{ cursor }`, for a bounded maximum of two pages.
- The detector publishes only `id`, `model`, `displayName`, `description`, `hidden`, `isDefault`, `defaultReasoningEffort`, and `supportedReasoningEfforts`, and independently filters `hidden: true` rows before publishing.

## Lifecycle and caching

- `detectCodexModels` mirrors the Claude detector: one cached result/promise per daemon process lifetime, with a 10-second timeout. This intentionally avoids repeated real `codex app-server` spawns while a daemon is running.
- The probe is started after socket `connect` and `startKeepAlive()` without awaiting it, so daemon connection and session creation stay off the app-server handshake path.
- `stopCodexModelProbe()` runs during daemon shutdown. Timeout, failure, and shutdown all call `disconnect()` so the app-server subprocess is cleaned up. Failed or unavailable probes resolve to `undefined`.

## Metadata and picker wiring

- Added optional `MachineMetadataSchema.codexModels`: an array of the trimmed model shape above, with `.optional().catch(undefined)` so older CLIs, offline machines, and failed probes retain the hardcoded fallback.
- Mirrored the schema in the app's storage types.
- `SessionView` passes `machine?.metadata?.codexModels` to `getAvailableModels()`. Its Codex branch now calls `getCodexModelModes(codexModels)`; absent or empty live metadata retains the existing four-row hardcoded fallback. The existing effort tables were not changed.
